# 問題セットの追加・修正ガイド（Claude 向け手順書）

このファイルは、ユーザーが授業資料を送って「この授業資料からクイズを作成して追加して」と依頼したときに、Claude が従う手順です。

## 0. 前提ルール

- **授業資料を最優先の根拠**とし、資料にない内容は出題しない。
- 薬学部の試験対策レベル。丸暗記だけでなく、理解・応用を問う問題も入れる。
- 正解が1つに決まらない曖昧な問題は作らない（「誤っているものを選べ」の場合も、誤りが1つだけになるよう確認）。
- 計算問題は、計算結果・単位・有効数字を検算する。
- 全問に解説をつけ、可能なら `sourcePage`（例 `"p.12"` `"スライド8"`）を記録する。
- 4択（choice）・○×（truefalse）・穴埋め（fill）を必ず混ぜる。配分は内容に応じて決める。

## 1. 作成 → ユーザー確認（ここで止まる）

1. 資料を読み、**まとめ**（6章）と **10〜20問** を作る。問題数は内容の量に合わせて決め、水増しや重複で数を合わせない。
2. まとめの内容と、問題・選択肢・正答・解説・根拠ページを **一覧でユーザーに提示** する。
3. ユーザーがまとめと全問を確認し、**公開を許可するまでファイルを追加しない**。修正依頼があれば直して再提示。

## 2. ファイルを追加する

1. `content/quiz-sets/<セットID>.v1.json` を作る（形式は下記・サンプルを参照）。
   - セットID：半角英小文字・数字・ハイフン。例 `basic-pharmacology-06`（科目＋回数）。**一度公開したIDは変えない**。
   - `subjectId` は `content/subjects.ts` の id。新しい科目なら、そのファイルに1行追加する。
2. `content/quiz-sets/index.ts` に import を1行、配列に1要素を追加する（既存行は消さない）。
   まとめは `content/notes/<セットID>.json` を作り、`content/notes/index.ts` に同様に登録する。
3. `npm run validate:quizzes` と `npm test` を実行し、エラーがないことを確認する。
4. GitHub に push（できない場合は、変更ファイルと操作手順をユーザーに案内）→ Vercel が自動で再デプロイ。
5. **Vercel のデプロイ完了と、公開サイトでセットが表示されることを確認できるまで「公開完了」と報告しない。**

## 3. JSON の形式

```json
{
  "id": "basic-pharmacology-06",
  "version": 1,
  "subjectId": "basic-pharmacology",
  "title": "第6回 自律神経系の薬理",
  "lectureDate": "2026-11-14",
  "published": true,
  "sourceMaterial": "基礎薬理学 第6回 授業スライド",
  "questions": [
    { "id": "q01", "type": "choice", "prompt": "…", "options": [{"id":"a","text":"…"},{"id":"b","text":"…"},{"id":"c","text":"…"},{"id":"d","text":"…"}], "answer": "b", "explanation": "…", "sourcePage": "p.3" },
    { "id": "q02", "type": "truefalse", "prompt": "…", "answer": false, "explanation": "…", "sourcePage": "p.5" },
    { "id": "q03", "type": "fill", "prompt": "…は [[blank]] を活性化する。", "options": [{"id":"a","text":"…"},{"id":"b","text":"…"},{"id":"c","text":"…"}], "answer": "a", "explanation": "…", "sourcePage": null }
  ]
}
```

| 項目 | ルール |
|---|---|
| 問題数 | 10〜20問。内容に合わせて決める（出題順＝配列の順・固定） |
| choice | 選択肢ちょうど4つ。`answer` は選択肢の `id` |
| truefalse | `answer` は `true`（○）か `false`（×）。`options` は書かない |
| fill | `prompt` に `[[blank]]` をちょうど1つ。選択肢3〜6個 |
| explanation | 必須 |
| ファイル名 | `<id>.v<version>.json` |

## 4. 公開済みの問題を修正するとき（重要）

過去の回答データとの整合性を保つため、**公開済みファイルは書き換えません**。

1. 旧ファイル（例 `xxx.v1.json`）はそのまま残す。
2. 内容をコピーして `xxx.v2.json` を作り、`"version": 2` にして修正する。
3. `index.ts` に v2 を追加（v1 の行も残す）。
- 表示・新しい挑戦は自動で最新バージョンになります。
- 過去の挑戦の得点と復習は、その挑戦が使ったバージョンで表示されます。
- 平均正答率はセットIDごとに全バージョン通算です。過去の得点はそのバージョンで採点済みのため、再計算しません。
- 進行中だった旧バージョンの挑戦は「最初から」になります（途中の分は平均に含めません）。

誤字修正など採点に影響しない軽微な変更でも、原則は新バージョンにしてください。

## 5. 非公開・削除

- 一時的に隠す：最新バージョンの `"published": false`。各端末の記録は残ります。
- JSON ファイル自体の削除はしない（過去の挑戦の復習が表示できなくなるため）。

## 6. まとめ（学習ノート）の作り方

問題セットごとに1つ、`content/notes/<セットID>.json` に置きます。セット一覧の「📖 まとめ」と、結果画面の「まとめで復習する」から開けます。
まとめは得点に関係しないので、**バージョンを上げずにそのまま書き換えてOK** です。

### 書き方のルール

- 授業資料に書いてあることだけをまとめる（資料にない知識を足さない）。
- やさしい言葉で、1文を短く。たとえ（「受容体は鍵穴🔒」など）を使ってよい。
- **絵文字を多めに**：各セクションの `emoji`、箇条書きの先頭、表のラベルなどに。ただし1文に何個も並べすぎない。
- クイズで問われる内容は必ずまとめに入れる（まとめを読めばクイズが解ける状態に）。
- 試験で間違えやすい点は `caution`、覚え方・語呂合わせは `tip` に。
- 計算は `formula` に公式と計算例を書き、数値と単位を検算する。
- 各セクションに `sourcePage`（例 `"p.3–5"`）を、わかる範囲で記録する。
- 目安：5〜8セクション、3〜5分で読める量。

### 形式

```json
{
  "setId": "basic-pharmacology-06",
  "lead": "ひとことで言うとこの回は何？（絵文字OK）",
  "goals": ["🎯 この回でわかること1", "📈 わかること2"],
  "sections": [
    {
      "emoji": "🔑",
      "title": "見出し",
      "color": "pink",
      "sourcePage": "p.3",
      "blocks": [
        { "type": "text", "text": "文章。**太字** や ==マーカー== が使える" },
        { "type": "points", "items": ["🟢 箇条書き", "🔴 箇条書き"] },
        { "type": "steps", "items": ["順番1", "順番2"] },
        { "type": "table", "headers": ["列1", "列2"], "rows": [["a", "b"]] },
        { "type": "tip", "label": "💡 覚え方", "text": "覚え方・コツ" },
        { "type": "caution", "text": "ひっかけ・注意" },
        { "type": "formula", "formula": "CL = k × Vd", "note": "補足", "example": "計算例" }
      ]
    }
  ],
  "keywords": [{ "term": "用語", "desc": "やさしい説明" }]
}
```

| 項目 | ルール |
|---|---|
| color | pink / sky / purple / yellow / mint（省略すると自動で色分け） |
| table | 各行の列数を headers と同じにする。スマホで読めるよう3列までが目安 |
| 文章の装飾 | `**太字**` と `==マーカー==` のみ |

`npm run validate:quizzes` でまとめの形式もチェックされます。
